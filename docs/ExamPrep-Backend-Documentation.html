1. What this backend is

ExamPrep API powers a competitive-exam prep product (SSC, Banking, Railways, UPSC, CAT, State PSC). It serves authentication, syllabus/notes, daily drills, timed topic tests, full mocks, analytics data, competition (battle) mode, reminders, exam config, and an optional AI explainer.

  • Repo path: backend/
  • Entry: server.ts → createApp() in src/app.ts → /api router
  • Dev: npm run dev (tsx watch) · Prod: npm run build → node dist/server.js

3. Boot & request pipeline

3.1 Process start (server.ts)

  1. Load .env only when not on Render (hosted uses dashboard env).
  2. validateEnv() — production requires Mongo, JWT_SECRET (≥32), FRONTEND_URL.
  3. connectDB() — hosted exits if Mongo fails; local can run degraded.
  4. Mount Express app, start reminder cron (every minute unless REMINDER_CRON=0).
  5. Listen on PORT (default 5000).

4. Auth system

This is the most important story to tell in an interview: secure session design with OTP, Google, and tokenVersion invalidation.

4.1 Flows

Register → email OTP (pending user in OtpChallenge) → verify OTP creates User → password login → JWT
Login (unverified) → force OTP again → then password login
Google → verify ID token (preferred) or auth-code → upsert user → JWT
Forgot password → OTP → reset (+ bump tokenVersion) → login
Logout → tokenVersion++ → old JWTs rejected

4.2 Design choices worth explaining

  • Register does not create User immediately — password hash + profile sit in OTP pendingData until email verify.
  • OTP codes are hashed (HMAC with pepper), TTL 10 minutes, max 5 attempts.
  • Forgot password never reveals whether an email exists (anti-enumeration).
  • Gmail aliases (dots / plus / googlemail) matched so OTP/login don’t break.
  • Admin role only from ADMIN_EMAIL — never trusted from the client.
  • JWT carries tv (tokenVersion) — logout & password reset invalidate all sessions.
  • Google preferred path = ID token (no client secret). Code flow optional if GOOGLE_CLIENT_SECRET set.
  • Passwords: bcrypt cost 12; legacy SHA-256 upgraded on successful login.

7. Security checklist

  • Helmet + COOP for Google popups + FedCM Permissions-Policy
  • Strict CORS allowlist (prod Vercel + FRONTEND_URL / FRONTEND_URLS)
  • Global + auth + OTP + AI rate limits on hosted
  • Body size cap 2mb; HPP; Mongo operator / prototype pollution sanitize
  • express-validator on auth/progress bodies
  • No stack traces to clients in production
  • CSV export escapes formula injection (=, +, -, @)
  • trust proxy on Render for correct client IPs

10. Deploy (Render)

  • Blueprint: render.yaml — web service ssc-backend, free Node, health check /health
  • Build: npm install && npm run build (postinstall also builds)
  • Start: node dist/server.js
  • Cron every 5 minutes hits /keepalive to reduce free-tier sleep
  • Frontend on Vercel proxies /api/* → this Render host
